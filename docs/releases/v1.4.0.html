What's new in 1.4.0

  • Reviews without cloning. The new Reviews section lists your team's open pull and merge requests and opens them without cloning the repository.
  • Review pull requests in gitForge. Approve, request changes, comment on any line in the Files tab and merge, without opening GitHub or GitLab.
  • Pull requests in ⌘K. Find your team's pull requests from the command palette, open one by pasting its link, or search everything on a server.
  • Choose what Reviews follows. Follow repositories by path pattern or by hand, hide the ones you don't want, and manage them in Settings › Reviews.
  • A clearer history graph. History draws your branch as a straight line, keeps rows in place as more history loads and joins Uncommitted changes to your commit.
  • See what a pull would bring. Commits that are only on the server show as dashed ghosts in History, each branch shows how far ahead or behind its remote it is, and the Remote branches toggle adds the rest.

Fixes

  • Creating a branch with checkout, including Check out branch on a pull request, no longer fails.
  • After checking out a commit, gitForge no longer keeps showing the previous branch as current.
  • Long branch names in a pull request's header are truncated in the middle instead of running past it.
  • GitLab merge requests show as !N, and large numbers no longer get a thousands separator.
  • History rows no longer draw a stale graph after a reload.
  • Lines in the history graph no longer show a notch on every row on non-Retina displays.

Improvements

  • When local changes block a pull, gitForge offers to discard only the files in the way and pull again.
  • Stashes made or dropped from the terminal show up in History without refreshing.
  • A fetch keeps your selection and scroll position in History.
  • gitForge shows what's new the first time it opens after an update, and Help › What's New in gitForge shows it again.
